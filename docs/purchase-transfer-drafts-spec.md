# 規格草案：轉單、合併與暫存

狀態：使用者已核准流程與儲存方案；本機實作完成，正式初始化與部署待另行授權。

## 目標與假設

讓老闆承接員工補貨需求，調整後另開採購單；在等待商品更新時，保留已選商品、數量及備註，不必重新選購。

已確認：勾選多張需求合併為可修改草稿、關閉 LINE 後可繼續、正式送單後原單標記已轉單並由新單統一追蹤。其餘細節採以下建議：

1. 勾選一張或多張待確認需求，建立一張採購草稿，也可從空白草稿開始。
2. 相同 SKU 合計數量，不同 SKU 各自保留；保留來源單號與原始需求以便核對。
3. 老闆可新增商品、調整數量或移除不採購品項。
4. 草稿關閉 LINE 後仍可恢復；以已驗證使用者識別，建議持久儲存於後端。
5. 正式送單前原需求保持待確認，但須顯示已被草稿引用，避免重複承接；正式送單時標示已轉單並連結新單，停止原單催辦。
6. 新採購單統一追蹤到貨，不再向原單重複登記到貨或回寫庫存。

## 現況依據

- `public/app.js` 使用記憶體中的 `cart` 與 `orderDraft`，目前沒有持久暫存。
- 既有確認下單流程支援追加任意可補貨 SKU、調整原品項數量，但沿用原單號。
- `src/sheets/repository.js` 目前將已完成、取消視為結案；新增已轉單須同步檢查查詢、提醒、通知與到貨流程。
- 資料後台為 Google Sheets，新增持久草稿與來源關聯可能需要新增分頁或欄位，具體結構待流程確認後設計。

## 建議使用流程

待確認需求 → 勾選來源 → 轉成採購草稿 → 調整／合併 → 暫存 → 更新商品清單 → 繼續編輯 → 確認送單 → 新單追蹤到貨。

草稿恢復或更新商品時，以 SKU 對應最新商品資料，保留輸入的數量及備註。不存在或停用的 SKU 應保留在草稿並提示處理，不可默默刪除或換成其他規格；送出時重新驗證。新增商品更新後可繼續加入。

## 驗收條件

- 可由單張或多張來源需求建立草稿，查看所有來源。
- 相同 SKU 合併後數量正確，仍能查看原需求。
- 關閉再開啟可恢復草稿內容；保存失敗有清楚提示，不顯示為已保存。
- 更新商品清單不清空既有選擇，新增商品可繼續加入。
- 不可採購的 SKU 必須明確處理後才能正式送出。
- 草稿不建立正式下單、到貨或庫存回寫事件。
- 正式送出前重新驗證身分、權限、來源狀態與商品資料。
- 雙擊、重送或多人同時操作不得重複轉單；失敗時不得只更新部分來源。
- 已轉單來源不再被當作獨立未結案需求重複催辦或計算。
- 草稿捨棄後來源可重新處理；來源已取消或已下單時，舊草稿不得直接送出。
- 維持既有每單 50 個唯一 SKU 的限制，合併超過時明確提示。

## 技術與結構

沿用 Node.js 22+、ESM、Express、原生網頁、LINE 身分驗證與 Google Sheets repository，不預設新增套件。

- `public/app.js`、`public/index.html`、`public/styles.css`：草稿與來源選擇操作。
- `src/routes/api.js`、`src/services/workflow.js`：草稿、轉單驗證與 API。
- `src/sheets/repository.js`：草稿持久化、來源關聯與一致寫入。
- `src/services/requests.js`、`src/services/reminders.js`、LINE 訊息相關模組：已轉單查詢、統計、催辦與通知。
- `test/`：服務、API、repository 與前端資料轉換測試。

## 驗證方式與指令

- 針對草稿恢復、目錄更新、合併、來源衝突、權限、重送及到貨不重複建立測試。
- 使用 `node --test` 執行新增的指定測試。
- 完整測試：`npm.cmd test`。
- 語法檢查：`npm.cmd run lint`。
- 建置檢查：`npm.cmd run build`。
- 本機開發：`npm.cmd run dev`。
- 手機驗收需涵蓋 LINE 關閉再開、保存失敗及商品更新後接續編輯。

## 邊界

- 一定做：後端權限驗證、來源追溯、防重送、保存失敗提示、測試既有流程不退化。
- 需確認：轉單入口、原單狀態、草稿持久性；新增正式 Sheet 分頁／欄位及正式部署須另行確認。
- 不做：直接向供應商購買、擅改飛鼠商品、修改既有正式訂單，或覆蓋工作區其他未提交變更。

## 資料結構（本機實作，尚未套用正式表）

新增三個分頁，不挪動既有補貨追蹤欄位：

| 分頁 | 建議欄位 |
| --- | --- |
| 採購草稿 | 草稿ID、擁有人LINE ID、狀態、備註、預計到貨日、版本、建立時間、更新時間、正式單號、最後操作金鑰、最後操作、群組ID |
| 採購草稿品項 | 草稿ID、SKU、商品名稱快照、單位快照、數量 |
| 轉單關聯 | 草稿ID、來源單號、正式單號、狀態、建立時間、更新時間 |

草稿狀態為編輯中／已送出／已捨棄，關聯狀態為保留中／已轉單／已釋放。同一來源只允許一個有效關聯；草稿捨棄時釋放。原單內容保留，僅正式送出時將其狀態設為已轉單。既有 Sheet 狀態驗證與公式需在上線前讀取並確認是否需調整。

草稿以擁有人隔離，只有已啟用的採購確認或管理員可操作自己的草稿。每人可存多張草稿。以明確「儲存草稿」按鈕及未儲存提示作為第一版保存方式；儲存成功才顯示已保存。

版本用於拒絕過期編輯；正式送出沿用操作金鑰及單一寫入佇列，來源更新、新單、關聯與操作紀錄須一致成功。部署腳本目前指定單一 instance，但仍須確認多 revision 重疊與正式部署條件，不能把程式內佇列當作跨服務鎖。
