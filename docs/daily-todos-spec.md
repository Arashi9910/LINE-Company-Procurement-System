# 每日固定待辦與下班確認

2026-09-17 已確認：初始工作全部「待指派」；管理員可新增工作及設定負責人；未完成工作隔天繼續列出。已授權本機實作，正式環境啟用另行確認。

## 目標與使用流程

在既有公司 LINE 群組管理每日基本工作與額外交辦，保留每日、每項、每人的完成紀錄。

- 台灣時間週一至週五 12:00，依固定範本建立當日工作，推送今日待辦與負責人。
- 同日 19:30，推送當日完成狀態，未完成項目提供「✅ 完成」按鈕。
- 白天亦可透過「今日待辦」查詢並完成，不必等到下班。
- 完成按鈕記錄工作 ID、原工作日期、實際操作人與時間；重複點擊不重複寫入。
- 每天生成獨立工作，不沿用昨天的完成狀態。舊卡片只操作該卡片對應工作。
- 群組內回覆簡短完成確認；查詢時取得最新狀態，不假設既有 LINE 訊息可原地修改。

## 暫定規則與待確認事項

- 中午及晚上皆僅週一至週五；暫不排除國定假日，不額外處理補班日。
- 初始固定事項：發貨、缺貨採購、取退貨、選品、上架、活動策劃。全部待指派，可後續新增或改名。
- 每項先採一位負責人；名字僅用於顯示，授權以 LINE user ID 為準。
- 只有已啟用的管理員可設定固定事項、指派、增加或取消工作。
- 只有已啟用的該項負責人可確認完成；管理員可改派，不默默代替員工打勾。
- 未指派工作顯示「待指派」，不能任意由他人完成。
- 昨日未完成保留原工作，在查詢及排程中列出「先前未完成」，今日固定工作照常產生。
- 未完成狀態不自動改為完成；額外交辦預設是當天單次工作，不加入每日範本。

## 群組操作草案

```text
今日待辦
新增待辦 @成員 整理新品照片
新增固定待辦 @成員 發貨
指派待辦 <工作編號> @成員
停用固定待辦 <範本編號>
取消待辦 <工作編號>
```

@成員必須使用 LINE 原生提及資料；拒絕只有文字姓名、多人提及或缺少 user ID 的指派。
固定範本異動預設從下一個尚未生成的工作日生效；當天改派使用工作編號。
首版訊息範例（人名為示意，非真實人員設定）：

```text
【今日待辦｜9/17】
□ 發貨｜小王
□ 缺貨採購｜小陳
□ 取退貨｜待指派

【下班確認｜9/17】
✅ 發貨｜小王
□ 缺貨採購｜小陳  [✅ 完成]
□ 取退貨｜待指派
已完成 1 / 3 項
```

## 技術與資料結構

沿用 Node.js 22+、Express 5、LINE SDK、Google APIs、Google Sheets 與 Cloud Scheduler，不新增套件。

計畫新增分頁（只列設計，尚未建立正式資料）：

1. `每日待辦範本`：範本 ID、事項、負責人 ID／顯示名稱、啟用、建立與修改時間。
2. `每日待辦紀錄`：工作 ID、日期、來源範本 ID 或單次交辦事件 ID、事項快照、負責人、狀態、完成者與時間、建立者、群組。
3. `待辦推播紀錄`：群組、日期、時段、狀態、固定重試識別碼、訊息快照、建立與更新時間；錯誤由 Cloud Logging 留存。
4. `待辦操作紀錄`：LINE 事件識別、操作人、動作、目標、時間與結果，供防重與追溯。

範本與歷史工作分離。工作以日期＋群組＋範本 ID 防重；額外工作以 webhookEventId 防重。
沿用既有單執行個體與序列寫入策略；跨請求防重結果必須持久保存，不能只存在記憶體。

建議檔案：

- `src/services/daily-todos.js`：日期、生成、指派、完成與推播流程。
- `src/sheets/daily-todos.js`：待辦專用資料讀寫；透過現有 repository 組合。
- `src/routes/webhook.js`：指令與 postback 入口，沿用簽章與群組檢查。
- `src/routes/jobs.js`：受既有排程密鑰保護的待辦入口。
- `src/line/daily-todos.js`：清單與完成按鈕；接入現有 messenger。
- `scripts/`：可預覽的分頁初始化及獨立排程設定工具。
- `test/`：使用 Node.js node:test 與假的 Sheets／LINE 依賴驗證。

## 排程與錯誤處理

- Cloud Scheduler 時區 `Asia/Taipei`，中午 `0 12 * * 1-5`，晚上 `30 19 * * 1-5`。
- 排程時間是觸發時間，不保證 LINE 精準於該秒送達。
- 服務端再次檢查工作日、時段與通知開關；跨日延遲不補發舊清單。
- 同日同時段重送不重複生成或推播。LINE 推播重試使用持久保存的 retry key，需依官方規格處理已接受回應與有效期間。
- 推播失敗保留可重試狀態；發送成功但落盤失敗時不能換新 key 盲目重送。
- 清單超過單則訊息限制需分頁；每頁保存獨立發送狀態及 retry key。
- 未設定群組、不完整表頭、權限不足時停止該操作並回報可理解的錯誤。
- 不在日誌列出密鑰或完整私人資料；新增工作、指派、完成、取消均留下稽核紀錄。

## 邊界

- Always：沿用既有授權及架構、驗證輸入、保存每日紀錄、執行測試。
- Ask first：正式 Sheets 新增分頁或寫入、部署、排程啟用、實際發送群組訊息；新增依賴。
- Never：提交密鑰或真實 LINE IDs、以名字當權限依據、自動勾選未完成工作、刪除既有補貨資料。

- 程式與本機驗證已實作；正式分頁、部署及排程尚未變更。上線步驟見 daily-todos-usage.md。
