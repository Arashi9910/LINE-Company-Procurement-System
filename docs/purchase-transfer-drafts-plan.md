# 實作計畫：轉單、合併與暫存

依據 `purchase-transfer-drafts-spec.md`。本機功能與測試已完成；正式初始化及部署已於 2026-09-29 取得授權並完成。真實手機 LINE 操作待使用者首次使用驗收。

## 1. 草稿保存與恢復

- 新增草稿資料模組與初始化程式，預設只檢查／列出變更，不直接修改正式試算表。
- 建立草稿的建立、列表、讀取、保存、捨棄 API，驗證角色、擁有人、版本及操作金鑰。
- 在商品選擇頁加入草稿入口、保存與恢復，允許多張獨立草稿。
- 驗收：重新開啟可恢復；無權者不能存取；舊版本不能覆蓋新版本；保存失敗保持未儲存提示。
- 驗證：服務與 repository 測試、API 測試、頁面人工操作。
- 主要檔案：新增草稿服務與儲存模組；`src/routes/api.js`；新增前端草稿模組；相關測試。各階段拆成不超過約五個檔案的變更。

## 2. 商品更新後接續編輯

- 加入重新載入商品操作，按 SKU 對應已保存內容，保留數量、日期、備註與無效品項。
- 商品停用／不存在時顯示提示並阻止直接送出，讓老闆移除或自行另選規格。
- 驗收：更新目錄後新增 SKU 可選、舊選擇不遺失、同名不同 SKU 不會誤替換。
- 驗證：商品對應單元測試與前端流程檢查。
- 主要檔案：前端草稿模組、`public/app.js`、`public/index.html`、`public/styles.css`、相關測試。

## 3. 勾選來源與合併

- 提供待確認來源清單，多選轉成草稿，保留來源單號、申請人與原需求。
- 相同 SKU 合計；超過 50 個品項或數量上限時清楚拒絕。
- 有效關聯阻止來源同時加入其他草稿；捨棄釋放。既有確認下單／取消流程須檢查關聯或使草稿明確失效。
- 驗收：多單合併正確、原需求可核對、重複轉入被阻止、來源失效有提示。
- 驗證：來源衝突、重送、捨棄與合併測試。
- 主要檔案：草稿服務、草稿儲存、前端草稿模組、`src/sheets/repository.js`、相關測試。

## 4. 正式送出與追蹤

- 重新驗證來源、SKU 與角色，建立新單並標記來源已轉單，記錄關聯與操作人。
- 只在新單登記到貨與飛鼠回寫；原單明細顯示新單連結。
- 已轉單來源從未結案統計、重複需求提示與催辦排除；更新狀態查詢與 LINE 通知。
- 驗收：正式送出整批成功、重送回傳同一結果、原單停止催辦、庫存只依新單到貨回寫。
- 驗證：repository、API、群組查詢、提醒及訊息測試；送出失敗情境。
- 主要檔案分階段修改：草稿服務／儲存與 API；再處理群組查詢、提醒、訊息及前端明細。

## 5. 完整驗證與上線準備

- 執行 `npm.cmd test`、`npm.cmd run lint`、`npm.cmd run build`。
- 手機驗收合併 → 保存 → 關閉 → 商品更新 → 恢復 → 正式送出 → 到貨。
- 讀取正式 Sheet 現有狀態驗證與公式，列出需要調整的精確範圍；確認單一 writer 的部署條件（待上線階段）。
- 提供正式資料初始化與部署清單，獲得授權後才套用。
- 保留既有 `src/services/flyingmouse-catalog-job.js` 與 `test/flyingmouse-catalog-job.test.js` 的未提交變更。
