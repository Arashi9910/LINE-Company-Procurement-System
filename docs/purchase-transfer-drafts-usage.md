# 採購草稿、轉單與合併

## 操作

1. 以已啟用的採購確認／管理員身分開啟補貨頁。
2. 點「採購草稿／合併需求」，勾選待確認來源並合併。可查看每張來源的品項；相同 SKU 加總。
3. 或先選商品，點「將目前選擇存成新草稿」。在原單確認下單頁使用此按鈕，也會保留當下調整的數量並關聯原單。
4. 編輯商品、數量、備註及預計到貨日。第一版使用手動「儲存草稿」；看到已儲存後才關閉 LINE。
5. 重開後從草稿列表繼續。「更新商品清單」保留已選數量及備註；新品可繼續加入。停用或不存在的 SKU 保留提示，需移除後重新選規格。
6. 點「確認正式送出採購單」。系統先保存變更，再建立正式新單，並把來源需求標記已轉單。
7. 後續到貨只登記新單。原單明細可開啟新單，新單明細可查來源。群組輸入「查已轉單」查看來源紀錄。

儲存不發送下單通知、不建立到貨或庫存異動。每人可保存多張草稿，只能操作自己的草稿。來源保留期間不可直接下單或取消；捨棄草稿後重新開放。原單的待確認提醒在正式送出轉單後停止。

## 錯誤處理

- 儲存失敗：頁面保留已選內容與未儲存提示，可再按儲存。
- 其他頁面已儲存：拒絕舊版本覆蓋；重新開啟最新版，再調整。
- 送出失敗：同一操作可重試；若資料已寫入而回應遺失，重試回傳同一張正式單。
- 群組通知失敗：正式單保留；依畫面提示使用「查已下單」。
- 來源被人工改成已下單／取消：阻止送出，捨棄後重新勾選仍待確認來源。
- 沒有選品項、無效到貨日、超過 50 個 SKU 或單項超過 999999 件：拒絕正式送出。
- LINE 直接關閉時不一定觸發瀏覽器離開提醒，務必先按儲存並確認成功。

## 正式啟用前

本次僅修改本機程式。未連線寫入正式 Sheet，未部署。

1. 先取得正式寫入及部署授權，備份原表。
2. 預覽新增分頁：`node scripts/setup-purchase-drafts.mjs`，此模式不連線。
3. 授權後初始化：`node scripts/setup-purchase-drafts.mjs --apply --spreadsheet <ID>`。遇到既有欄位不符會停止，不覆蓋內容。
4. 三個分頁為「採購草稿」「採購草稿品項」「轉單關聯」，完整欄位由初始化程式輸出。狀態、版本、操作金鑰等由系統維護，不手動編輯。
5. **人工核對原表狀態驗證及公式**：G 欄需允許已轉單；K 未到量、L 重複提示、條件格式及任何人工報表不得把已轉單來源當作待採購。初始化程式只建立新分頁，不猜測或重寫既有公式。
6. 保持單一寫入服務。現有寫入佇列只保護單一 Node.js 程序；本功能沒有跨程序鎖。**不支援多 instance、多 revision 同時接受寫入，亦不支援人工並行改動系統欄位。** 啟用與後續部署需安排停止寫入的窗口，避免舊版與新版同時服務；`--max-instances 1` 本身不能取代這個檢查。
7. 設定 `PURCHASE_DRAFTS_ENABLED=true`，部署腳本提供 `-EnablePurchaseDrafts`；現有其他功能開關應依原部署配置保留。
8. `/ready` 會驗證新分頁欄位。以測試需求實測保存、關閉重開、合併、轉單、群組通知與新單到貨，再開放使用。

## 維護限制

- 沿用 Google Sheets，未新增套件或外部資料庫。讀取草稿表會消耗既有 API 配額。
- 新分頁預設容量 20000 列。已送出與捨棄草稿保留追溯資料，滿額前需規劃封存；目前不自動刪除。
- 第一版每張單使用一個預計到貨日，沿用既有頁面的操作習慣。
- 已送出草稿不能再編輯，已轉單來源不恢復成待確認；取消新採購單不會自動重開原需求。
- 真實 LINE WebView、正式 Sheet 的公式與驗證規則仍需上線驗收；本機瀏覽器測試使用模擬 LINE 身分與記憶體試算表。
