## 2. 這一輪做了什麼

### 2.1 名稱來源：貨品層 → 銷售商品層

飛鼠有兩層名稱，**兩層都是現況但內容會不一樣**。官方 Excel 匯出的是貨品層，
所以 SKU主檔 一路沿用建檔當下的舊名稱。實測 1625 列有 215 列前綴不一致
（「預售」vs「隔日到貨」），導致採購把現貨商品當成還在等上游而重複下單。

- 補貨顯示名稱（SKU主檔 H）改用銷售商品名稱，來源是每小時同步**既有**的
  `captureFlyingMouseProductList`，不增加飛鼠負擔。
- **B 欄必須維持貨品層的值**：`sheets-baseline.js` 拿 `A:D` 當與 Excel 的差異比對基準。
- 名稱漂移是**雙向的**：有商品貨品層寫「隔日到貨」而銷售商品層是「預售」。
  不要假設「貨品層總是比較舊」。

### 2.2 出貨型態欄

SKU主檔 O 欄、補貨追蹤 W 欄，值為 `現貨`／`預購`／`未知`。

- **只能由驗證過的銷售商品綁定決定**。查不到就寫「未知」，不要從名稱前綴猜——
  貨品層的前綴正是不可信的來源。
- **整輪都沒有銷售商品資料時（`--input` 路徑）完全不碰 O 欄**。那是「這輪沒查」，
  不是「每一支都不知道」，照寫會把上一輪正確的 1600 筆洗掉。
- 規格修正到貨時 W 欄要跟著換成新 SKU 的型態，否則該列結案後永久留著舊值。

### 2.3 貨號汰換

`docs/sku-retirement-spec.md`。飛鼠重新上架會換掉整組貨號，舊貨號的需求不會消失。

- 「貨號汰換」分頁 A～C 人工填、D～F 程式回寫。**對應一律人工填，程式不猜**：
  款式名稱兩邊一致，但顏色是商品個別的命名習慣（珍珠白→暖白色、胡桃色→胡桃木），
  推導不出來。
- 搬：未寄、近 30 天售出。不搬：飛鼠庫存、已叫貨未到（採購單下在舊貨號上，
  到貨也登記在舊貨號）。後兩者不為 0 就擋下整條。
- 目前正式環境有 22 條，全部已套用。缺貨清單的「不可補貨」已從 7 降到 0。

### 2.4 缺貨清單 LIFF 頁面

`docs/shortage-liff-spec.md`。`查缺貨` 從純文字改成摘要加按鈕。

- 分組走共用的 `groupShortageRows`，文字摘要與頁面吃同一份——各自分組遲早會
  出現「訊息說 27 個、頁面列出 25 個」。
- 卡片把**規格獨立一行**顯示。API 回傳 `spec` 與 `productName` 兩個欄位，
  **不要讓前端從「規格｜名稱」切回來**：商品名稱本身可能含「｜」。
- 有些缺貨列在 SKU主檔 是「不可補貨」。照樣列出但標成不可勾選——`submitRequest`
  本來就會擋，等送出才失敗更糟。

### 2.5 補貨顯示名稱：規格放最前面

商品名稱是蝦皮的關鍵字堆疊（50～60 字），規格接在尾巴時 Google Sheets 的欄寬
只看得到前 20 字，同商品的不同規格顯示完全一樣。2026-11-02 因此讓人把戒指的
採購單當成項鍊的。

格式是 `規格1｜規格2｜商品名稱`。**兩個 `buildDisplayName` 都要改**：
`sheets-operational.js`（每小時同步）與 `sheets-review.js`（核准匯入）。

## 3. 會咬人的地方

### 3.1 PowerShell 腳本必須純 ASCII

Windows PowerShell 5.1 對**無 BOM** 檔案用系統 ANSI（這台是 cp950）讀。
UTF-8 中文註解的尾端位元組會吃掉換行，把下一行併進註解——變數指派整行消失。
**語法檢查抓不到**，因為併進去之後仍是合法註解。

曾因此讓 Job 的 `INVENTORY_DASHBOARD_ENABLED` 變成空字串。`scripts/check.mjs`
已加上 `.ps1` 純 ASCII 檢查。

### 3.2 部署不會自動切流量

這個 Cloud Run 服務的流量釘在具名 revision，`gcloud run deploy` 不會覆蓋它：
新 revision 建好卻拿不到流量，舊版繼續服務，`/ready` 驗到舊 commit，部署判定失敗。
`deploy-gcp.ps1` 現在會自己切流量並確認 `latestReadyRevisionName` 相符。

回滾只要改流量，不必重新部署：

```
gcloud run services update-traffic line-replenishment --region asia-east1 \
  --to-revisions <舊 revision>=100
```

### 3.3 部署旗標漏帶就是關掉功能

`--set-env-vars` 是整組覆寫。`deploy-gcp.ps1` 必須帶齊：

```
-EnableFlyingmouseWriteback -EnableDailyTodos -EnablePurchaseDrafts -EnableInventoryDashboard
```

`deploy-flyingmouse-job.ps1` 預設是 `read-only` + `dry-run`，正式必須明確指定
`-SheetMode auto -WritebackMode live -ApproveLive -EnableInventoryDashboard`。

### 3.4 表頭是嚴格比對

SKU主檔、補貨追蹤、看板各分頁的表頭都是 `exactHeaders`／`assertSheetHeaders`，
少一欄整輪同步就停。加欄位要先跑遷移腳本再部署程式：

- `node scripts/setup-sales-name-sync.mjs --spreadsheet-id <id>`（出貨型態欄）
- `node scripts/setup-inventory-dashboard.mjs --apply --spreadsheet <id>`（看板四張分頁＋貨號汰換）

兩支都可重跑。後者對「系統分頁」只在表頭不符時才清資料列。

### 3.5 同步只更新來源有的列

`syncCatalogItems` 不會碰 `mainOnly` 的列（SKU主檔 有、官方 Excel 沒有）。
目前有 2 筆匹克球拍是這種狀態，所以它們的 H 欄還是舊格式。這是保護行為不是 bug，
但會讓「全部都改了嗎」的檢查對不齊，先知道比較好。

### 3.6 在途單回填有跨程序競態

每小時同步跑在獨立 Job，碰不到 `SheetsRepository` 的寫入佇列。
`refreshTrackingDisplayNames` 的做法是：有東西要寫時先重讀追蹤表，完全依最新那份
重算。殘留的一瞬競態要靠跨程序鎖才能消除，不在這次範圍。

## 4. 還沒解決的

1. **預購額度在到貨後會重新膨脹**（`docs/inventory-dashboard-spec.md` 第 6 節）。
   純預購商品的額度由庫存＋未寄推導，到貨後額度跟著漲，可能重複叫貨。
   Codex 先前建議的方向：未校正的預購 SKU 顯示「待確認」而不給確定缺口，
   只校正有訊號的，人工填寫的額度永遠優先。注意 `formatShortageSummary` 會過濾
   `gap > 0`，待確認的列要另外處理才不會消失。
2. **飛鼠有重複建檔的貨品**。只差一個空白的組合還有 13 組（兩邊都還開著，目前沒事）。
   根治要在飛鼠合併。
3. **`補貨指令` 的說明文字過時**：沒列 `補貨` 本身，待辦只列 3 個但實際有 12 個。
4. **`查缺貨` 不會因為資料過期而警告**。過期提示只在同步**失敗**時出現；
   排程若默默停了但沒報錯，狀態會一直是「正常」，指令會安靜地回舊資料。
